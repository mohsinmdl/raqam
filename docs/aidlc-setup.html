Brief

What's involved: Fetch the latest release zip ai-dlc-rules-v<n>.zip from github.com/awslabs/aidlc-workflows/releases/latest into the job tmp dir and extract it.

Why / how: Releases are the official install artifact per the awslabs/aidlc-workflows README — no repo clone needed. Everything lands in a throwaway tmp dir first, so a bad download touches nothing repo-side.

TMP=$(mktemp -d)
gh release download --repo awslabs/aidlc-workflows --pattern 'ai-dlc-rules-*.zip' --dir "$TMP"
unzip -q "$TMP"/ai-dlc-rules-*.zip -d "$TMP/aidlc"

What carries over / result: Extracted tree in tmp containing aws-aidlc-rule-details/ and core-workflow.md — the inputs for items 2 and 3.

Verify: ls "$TMP/aidlc" shows aws-aidlc-rule-details/ and core-workflow.md.

Cost: $0 · Risk: Network-only; GitHub flakiness (known per-IP TCP resets) just retries — nothing partial lands in the repo.

Brief

What's involved: Walk the user through how AI-DLC runs now that it is installed. No further repo changes.

Why / how:

  1. Restart Claude Code in the repo — CLAUDE.md rules load at session start, so the current session does not see them.
  2. Kick off any task with "Using AI-DLC, <intent>" — e.g. "Using AI-DLC, add a YNAB-style multi-Plan system (plan switcher, New Plan modal, per-plan currency & formats)".
  3. The agent runs Inception (structured questions → requirements → stories → design, all user-validated), then Construction (component design, code, tests), then Operations. Artifacts accumulate in aidlc-docs/.
  4. Hand over this session's exploration findings as Inception input: single-budget schema (supabase/migrations/0001_init.sql scopes every table by user_id only), sync trusts RLS with no filters (src/store/sync.js), currency hardwired to PKR/Rs/en-PK (src/lib/calc.js).

What carries over / result: User can drive the multi-Plan feature — and any later task — through AI-DLC as the first real run.

Verify: In a fresh session, "Using AI-DLC, …" visibly enters the Inception question flow instead of ad-hoc coding.

Cost: $0 · Risk: None — informational only.

What gets worse

  • Every future Claude Code session in this repo loads the AI-DLC workflow instructions — the full flow is gated behind the trigger phrase, but the instructions still occupy context on every session, including one-line fixes.
  • aidlc-docs/ artifacts will accumulate in-repo once tasks run through the methodology.
  • Upstream rule updates now require manual re-vendoring — and re-applying the merge-don't-clobber rule once a real project CLAUDE.md has grown around the workflow.

Out of scope (explicitly NOT doing)

  • The multi-Plan feature itself (plan switcher, New Plan modal, per-plan currency/formatting) — it becomes the first AIDLC-run task after this setup; building it now would defeat the pivot.
  • Any schema/sync/currency changes (supabase/migrations/0001_init.sql, src/store/sync.js, src/lib/calc.js) — this session's findings about them are handed to Inception as context, not acted on.
  • Merging or opening a PR for the setup branch — the approved plan ends at commit + push; integration is decided after the walkthrough.
